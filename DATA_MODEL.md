# Структура данных «КопиХвоста»

## Общая модель

Состояние игры хранится в одном объекте. Текущая версия структуры данных имеет номер **6**.

Основной ключ:

```text
finpet_mvp_state_v1
```

Для демонстрационного режима используется отдельное состояние:

```text
finpet_demo_state_v1
```

При загрузке старые версии данных проходят миграцию в `migrateState()`.

## Профиль

Ключевые поля:

| Поле | Назначение |
|---|---|
| `version` | версия структуры состояния |
| `difficultyMode` | текущий режим сложности: `easy` или `medium` |
| `onboardingDone` | завершено ли вводное знакомство |
| `createdAt` | время создания локального профиля |
| `settings` | настройки звука и анимации |

Регистрация по телефону, электронной почте или внешнему аккаунту не требуется.

## Питомец

Объект `pet` содержит:

| Поле | Назначение |
|---|---|
| `type` | тип питомца: кот, собака или Мумо |
| `name` | выбранное имя |
| `color` | цвет |
| `accessory` | аксессуар |
| `satiety` | сытость |
| `mood` | настроение |
| `energy` | энергия |
| `health` | здоровье |
| `development` | накопленный прогресс развития |

Основные показатели питомца ограничиваются диапазоном от 0 до 100.

## Кошелек

Объект `wallet` содержит:

| Поле | Назначение |
|---|---|
| `balance` | доступные игровые монеты |
| `savings` | монеты в копилке |
| `weeklyIncome` | базовый доход периода |
| `week` | номер игрового периода |
| `day` | текущий игровой день |
| `nextIncomeIn` | количество дней до следующего дохода |
| `needsSpent` | сумма расходов на необходимые потребности |

## Транзакции

Каждая финансовая операция сохраняется в `transactions`.

Основные поля записи:

| Поле | Назначение |
|---|---|
| `id` | уникальный идентификатор |
| `type` | доход, награда, расход, накопление или снятие |
| `amount` | сумма операции |
| `category` | категория финансового действия |
| `timestamp` | время операции |
| `description` | описание |
| `source` | источник операции |
| `week` | период |
| `day` | игровой день |
| `balanceAfter` | баланс после операции |
| `meta` | дополнительные данные |

В состоянии хранится до 180 последних транзакций.

## План бюджета

Для каждого периода используются:

- `weekPlan` как рабочий план;
- `initialWeekPlan` как подтвержденный план для последующего сравнения;
- `weekSnapshot` как снимок состояния в начале периода;
- `weekSummary` как итог периода;
- `weekHistory` как история завершенных периодов.

Подтвержденный план включает:

- `necessary` для необходимых расходов;
- `wants` для желаний;
- `savings` для накоплений;
- `reserve` для запаса.

После подтверждения исходный план периода не редактируется. Это позволяет честно сравнивать план и фактические действия.

## Финансовые цели

Используются поля:

- `activeGoal`;
- `goalContributions`;
- `goalAdjustments`;
- `completedGoals`;
- `wallet.savings`.

Сами цели и базовые суммы хранятся в `content.js`.

## Задания и достижения

Игровой прогресс заданий хранится в:

- `completedTasks`;
- `achievements`;
- `xp`;
- `stats.tasksDone`.

Повторное выполнение уже завершенного задания не должно повторно начислять основную награду.

## Предметы и игровой мир

Для купленных постоянных предметов используются:

- `inventory`;
- `worldPlacements`;
- `worldProgress`;
- `currentWorldArea`.

`worldProgress` хранит текущую стадию мира, доступные области, открытия и декор.

## События

Текущие и уже просмотренные игровые события фиксируются через:

- `currentEventId`;
- `currentChainId`;
- `eventResolved`;
- `recentEventIds`;
- `storyChains`.

Будущие обязательства от решений игрока могут храниться в `futureObligations`.

## Занятия

Состояние дополнительных занятий хранится в объекте `clubs`.

Он содержит выбранное занятие, историю оплат, пропуски, накопленный прогресс и полученные визуальные награды.

## Подработка

Для усложненного режима используются:

- `workState`;
- `workSession`;
- `activityLimits`.

Они ограничивают количество доступных подработок и сохраняют состояние текущей активности.

## Аварийная помощь питомцу

Если сытость, настроение или здоровье достигают нуля, переход к следующему дню блокируется.

Объект `emergencyCare` хранит случаи бесплатной экстренной помощи, чтобы игрок мог восстановить критический показатель даже при отсутствии монет.

## Совместимость данных

`migrateState()` обновляет старые сохранения до версии 6 и сохраняет совместимость с ранними полями, возрастными режимами, структурой здоровья, занятиями и обязательствами.

Подробные правила сохранения на Android приведены в [BUILD_ANDROID.md](BUILD_ANDROID.md).
