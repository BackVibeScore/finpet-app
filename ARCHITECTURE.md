# Архитектура проекта «КопиХвост»

## Назначение

«КопиХвост» представляет собой клиентское игровое приложение по финансовой грамотности. Основная логика работает на устройстве пользователя и не требует серверной части для прохождения игры.

Одна кодовая база используется для веб-версии, PWA и Android-приложения.

## Технологический стек

- HTML5;
- CSS3;
- JavaScript без обязательного frontend-фреймворка;
- Service Worker для кэширования веб-версии;
- Capacitor 8 для Android-оболочки;
- Capacitor Preferences для долговременного хранения состояния на Android;
- Gradle и Android SDK для сборки APK;
- GitHub Actions для автоматических проверок.

Основные зависимости и их версии зафиксированы в `package.json` и `package-lock.json`.

## Компоненты

### Интерфейс

`index.html`, `styles.css`, `welcome.css` и `welcome.js` формируют оболочку приложения, стартовый экран, адаптивную верстку и вводное знакомство.

### Игровая логика

`app.js` содержит:

- игровой цикл;
- бюджет и транзакции;
- покупки;
- накопления и финансовые цели;
- состояние питомца;
- задания;
- события;
- прогресс;
- демо-режим;
- навигацию;
- обратную связь после действий пользователя.

### Контент

`content.js` содержит игровые данные:

- питомцев;
- товары;
- цели;
- задания;
- образовательные темы;
- события;
- занятия;
- параметры экономики;
- тексты пользовательских сценариев.

Контент отделен от основной логики, поэтому задания, цены, награды и тексты можно изменять без переработки интерфейсного ядра.

### Хранение данных

`storage.js` отвечает за чтение, запись, резервирование и восстановление состояния.

В браузере используется локальное хранилище. В Android основным долговременным хранилищем является Capacitor Preferences.

Основной ключ состояния:

```text
finpet_mvp_state_v1
```

Демо-режим использует отдельный ключ:

```text
finpet_demo_state_v1
```

Это позволяет демонстрировать продукт без изменения обычного профиля пользователя.

### PWA

`sw.js` кэширует необходимые ресурсы веб-версии. `manifest.json` содержит PWA-метаданные.

### Android

`capacitor.config.json` описывает Android-приложение с идентификатором `ru.kopihvost.app`.

Скрипт `scripts/build-android-web.js` подготавливает веб-ресурсы для Android. После этого Capacitor синхронизирует их с Android-проектом, а Gradle формирует APK.

Нативная точка входа:

```text
android/app/src/main/java/ru/kopihvost/app/MainActivity.java
```

## Последовательность работы приложения

1. Приложение загружает контент и локальное состояние.
2. При необходимости сохранение приводится к актуальной версии структуры данных.
3. Пользователь проходит знакомство или возвращается в существующий профиль.
4. Игровая логика рассчитывает бюджет, состояние питомца, задания и события.
5. Каждое значимое финансовое действие фиксируется в журнале транзакций.
6. Измененное состояние сохраняется локально.
7. При завершении периода приложение сравнивает план и фактические действия и рассчитывает развитие питомца.

## Серверная часть и API

Серверная часть в текущей версии отсутствует.

Основной игровой сценарий не использует собственный backend, удаленную базу данных или обязательную авторизацию. Поэтому отдельная схема развертывания сервера и спецификация OpenAPI для текущей версии не требуются.

Внешний API не является частью игровой логики.

## Аналитика

Публичная веб-версия может использовать Яндекс.Метрику.

При подготовке Android-пакета код Яндекс.Метрики исключается. Точка расширения для мобильной аналитики предусмотрена через `window.FINPET_ANALYTICS`, но AppMetrica в текущей версии не подключена.

## Автоматические проверки

В репозитории используются два основных workflow:

- `Web validation`;
- `Android APK validation`.

Они проверяют игровую логику, контент, хранение данных, Android-сборку и регрессию ключевых сценариев.

Подробности приведены в [TEST_REPORT.md](TEST_REPORT.md).
